## Задача

Третий перехват: подтверждения действий.

1. Изучи контракт в DSH: `packages/interaction/user-approval/src/types.ts`
   (`ApprovalRequestEvent {agent, toolName, callId?, reason?, signal?}`,
   `ApprovalOutcome = 'allowed-once' | 'rejected' | 'cancelled' | 'unavailable'`,
   waterfall `approval/request`) и `docs/subsystems/approval.md`.
2. `dsh-remote/lib/approvals.js` + `dsh-remote/lib/features/approvals.js`:
   - подписка `ctx.on("approval/request", handler, { prepend: true })`;
   - режим выключен → `return next()`;
   - включён → собрать сообщение (шапка из 006 + `toolName` + `reason`),
     отправить в канал(ы) с кнопками `Разрешить один раз` / `Отклонить` /
     `Не отвечать`, дождаться решения, вернуть `ApprovalOutcome`;
   - `signal` абортится → закрыть сообщение «снято», вернуть `cancelled`;
   - падение транспорта → `next()` (GUI), как у вопросов;
   - фича подключается одной строкой в `lib/features.js`.
3. Модель решения — переиспользовать `RemoteQuestion`-подобную структуру
   (`kind: "approval"`), чтобы работали store/маршрутизация/дедуп.
4. Тесты `test/approvals.spec.js` на фейковом транспорте: разрешение, отказ,
   «не отвечать» → `unavailable`, аборт → `cancelled`, выключенный режим → `next()`
   ровно один раз, `prepend: true` в опциях подписки.
