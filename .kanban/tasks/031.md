## Задача

Метрики, по которым видно, что система делает и где тормозит.

1. `dsh-remote/lib/metrics.js` — счётчики и гистограммы в памяти:
   вопросы (`asked/answered/expired/cancelled`), подтверждения по исходам,
   доставки (`sent/failed/retried`), латентность (время до ответа), ошибки по
   транспортам, размеры очередей. Только числа — ни тел, ни id пользователей.
2. `/remote stats` — сводка за сессию плагина; `/remote stats --json`.
3. Публикация через `ctx.provide("remoteMetrics", …)`, чтобы панель (009) и
   `doctor` (030) могли читать без прямого импорта.
4. Тесты: инкременты в правильных местах (вопрос → asked, ответ → answered + латентность),
   сброс при старте, `--json` парсится, отсутствие секретов в дампе.

## Критерии готовности

- [ ] метрики не растут бесконечно (гистограммы — с фиксированными бакетами);
- [ ] `/remote stats` и `--json` покрыты тестами;
- [ ] в метриках нет секретов и тел вопросов;
- [ ] `node --test dsh-remote/test` зелёный.
