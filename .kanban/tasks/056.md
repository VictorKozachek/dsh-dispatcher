## Задача

После слияния `#051` журнал не пишется вообще: файла `~/.dsh/remote-control/log.jsonl`
нет ни после живых вопросов, ни после ответов, хотя фича поднялась (`boot.log`:
`features запущено 11/11: journal:ok, …`).

Причина — та же, что была у `remoteTransport` 11.11: **сервис регистрируется
только через `ctx.provide`**, а cordis с обычным объектом (не `Service`) этого не
делает. Наблюдатель получает `null`:

- `dsh-remote/lib/features/journal.js:32` — `ctx.provide?.(JOURNAL_SERVICE, journal)`;
- `dsh-remote/lib/features/answerer.js:242` — `journal: deps.get("remoteJournal") ?? null`;
- `dsh-remote/lib/commands.js:886` — `journal: ctx?.get?.("remoteJournal") ?? null`.

Итог: `journal.feature` жива, `createJournal` создан, но ответчик взять его не
может → `journalEvent()` молча ничего не пишет → файла нет (создание ленивое).

Подтверждено вживую 2026-11-13 22:31–22:40: вопросы доставлялись в MAX
(`POST /messages` в истории чата), но `log.jsonl` отсутствовал.

## Требования

1. `features/journal.js`: кроме `ctx.provide`, публиковать сервис через
   `deps.expose?.(JOURNAL_SERVICE, journal)` — как это сделано для
   `remoteTransport` в `features/commands.js`.
2. `answerer` должен получать журнал и в том случае, когда `deps.get` возвращает
   `null` (страховка: `deps.get?.(…) ?? ctx?.get?.(…) ?? null` — ровно так
   сделано для транспорта).
3. `commands.js`: то же самое для `/remote status`/`doctor` (строка про журнал).
4. **Тест на регресс**: ответчик, поднятый каркасом с `journalFeature`, пишет
   `question.send` в файл (без прямого `ctx.get` в тесте) — то есть проверяется
   именно дорога «фича → deps → ответчик», а не только `createJournal`.
5. Тест на отсутствие двойной записи (если сервис виден обоими путями).
6. `logFile: false` по-прежнему выключает запись, ошибка записи не ломает плагин.

## Критерии готовности

- [ ] после `apply` и вопроса файл `log.jsonl` содержит `question.send`/`question.sent`;
- [ ] `answerer` получает журнал через общий реестр (тест на каркас);
- [ ] `/remote status` показывает журнал (путь) без падения;
- [ ] тесты на выключение и на ошибку записи остаются зелёными;
- [ ] `node --test` и `bin/ci.sh --fast` зелёные.
