## Задача

На установке, где активен канал **MAX**, `/remote doctor` даёт `exit 2` из-за
проверки `credentials:DSH_REMOTE_TELEGRAM_TOKEN`, хотя Telegram по правилу 038
отключён и его токен удалён намеренно.

Причина: `dsh-remote/lib/commands.js:1550` строит список проверяемых секретов без
оглядки на активную привязку:

```js
const tokenRefs = relay === null ? [TELEGRAM_TOKEN_REF] : [TELEGRAM_TOKEN_REF, RELAY_TOKEN_REF];
```

Итог в живом отчёте (проверено 2026-11-12):

```
[ok]   channel: MAX … polling да
[fail] credentials:DSH_REMOTE_TELEGRAM_TOKEN
exit 2
```

То есть строка про канал верна, а отчёт в целом «красный» и врёт: секрет,
который мы сами удалили при переключении, объявляется проблемой.

## Требования

1. Список обязательных секретов строится **по активной привязке**:
   - `telegram` → `DSH_REMOTE_TELEGRAM_TOKEN`;
   - `max` → `DSH_REMOTE_MAX_TOKEN`;
   - `relay` → токен релея (как сейчас);
   - привязки нет → проверять только то, что задано конфигом (`config.telegram`/`config.max`),
     остальное не упоминать.
2. Секрет **отключённого** канала не считается проблемой, но его наличие —
   информационная строка (`[info] предыдущий канал: telegram (токен удалён)`).
3. `doctor` по-прежнему ловит реальные проблемы: привязка есть, токен пропал →
   `[fail]`; токен есть, канал не поднят → `[fail]`.
4. Тесты: MAX-only установка → `exit 0` и нет `[fail]` про telegram; telegram-only
   → нет `[fail]` про MAX; привязка max без токена → `[fail]` про MAX; отсутствие
   привязки → без `[fail]` про чужие токены.

## Критерии готовности

- [ ] `doctor` на MAX-only зелёный (exit 0);
- [ ] `doctor` на telegram-only зелёный;
- [ ] привязка без своего токена — по-прежнему красная с внятной строкой;
- [ ] тесты на четыре конфигурации;
- [ ] `node --test` и `bin/ci.sh --fast` зелёные.
