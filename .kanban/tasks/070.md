## Задача

Журнал (`~/.dsh/remote-control/log.jsonl`, `#051`/`#056`) уже пишет события по
вопросам, но посмотреть их можно только руками (`tail`). Нужен раздел в панели
«Удалённое управление»: последние вопросы с их судьбой.

## Требования

1. **Чтение журнала** — новый модуль (`lib/journal-read.js` или в `lib/panel.js`):
   - читает `log.jsonl` (и `.1` после ротации, если есть), построчно JSON;
   - битые строки пропускает и считает (`skipped`), не падает;
   - фильтрует по времени (по умолчанию последние 24 часа) и по проекту, если
     передан `workspace`.
2. **Сборка истории** — из событий `question.send` / `question.sent` /
   `question.error` / `answer.received` / `answer.unmatched` / `answer.dropped` /
   `pairing.*` собрать по `shortId` строку:
   `время · проект (если есть) · транспорт · shortId · статус`;
   статусы: `доставлен`, `ошибка доставки (код)`, `отвечен`, `не сопоставлен
   (причина)`, `снят`.
3. **Панель**: блок «История вопросов» — последние N (по умолчанию 20) строк:
   время, проект, статус, короткий идентификатор; клик по строке раскрывает
   детали (транспорт, `messageId`, `optionIds`/`customLength`, причина).
4. **Только чтение**: панель ничего не пишет в журнал и не двигает состояние.
5. **Приватность**: текст ответов и токены в панель не попадают — только длины и
   идентификаторы (в журнале их и так нет, но проверить).
6. **Тесты**: пустой журнал → «пока нет событий»; битая строка → пропущена и
   посчитана; полный цикл `send→sent→received` → статус «отвечен»; `send→error` →
   «ошибка доставки» с кодом; `received→unmatched` → «не сопоставлен» с причиной;
   ротация (`.1`) читается; фильтр по времени.

## Критерии готовности

- [ ] панель показывает историю вопросов (последние 24 часа, N строк);
- [ ] статусы различаются (отвечен / ошибка / не сопоставлен / снят) — тест;
- [ ] битые строки и ротация не ломают чтение (тест);
- [ ] в панель не попадают токены и тексты ответов (тест);
- [ ] `node --test` и `bin/ci.sh --fast` зелёные.
