## Задача

Живой сценарий 2026-11-17 (MAX): вопрос с вариантами, человек жмёт **«Другой
ответ»** → сообщение редактируется в «✅ Отвечено: Другой ответ», **дальше тишина**,
агент ждёт вечно. И непонятно, куда вводить текст.

### Причина (две, обе наши)

1. **Запись вопроса удаляется на любом колбэке.** `lib/transport/max.js`
   (ветка `message_callback`, ~строка 610):
   ```js
   emit({ shortId, optionIds: [parsed.optionId], … });
   await answerCallback(update.callback.callback_id, `✅ Отвечено: ${escapeHtml(label)}`);
   sent.delete(parsed.shortId);   // ← выполняется и для FREE_TEXT_OPTION
   ```
   После «Другой ответ» `sent` пуст, поэтому следующее текстовое сообщение не
   сопоставляется: `message_created` ищет запись по `sent.size === 1`/`reply.mid`
   (строка 620) и пишет в лог «свободный текст не к какому вопросу не относится —
   игнор». Вопрос остаётся открытым → ответчик ждёт до TTL — «повис навсегда».
2. **Нет приглашения ввести текст.** В Telegram после «Другой ответ…» мы присылаем
   отдельное сообщение с `force_reply` («✍️ Напишите ответ текстом»). В MAX такого
   нет: у платформы нет force_reply, но **сообщение-инструкция** нужно, иначе
   человек не знает, что делать.

### Что должно быть

1. При `FREE_TEXT_OPTION`:
   - **не** удалять запись из `sent` (вопрос всё ещё ждёт ответа);
   - отредактировать сообщение вопроса в «✍️ Напишите ответ текстом одним
     сообщением (можно ответом на это сообщение)» — кнопки снять;
   - отправить отдельное короткое сообщение-приглашение с текстом вопроса в шапке
     и подсказкой «напишите ответ в этот чат», чтобы было видно, к чему он
     относится;
   - только после этого ждать текст.
2. `sent.delete` выполнять **только** для реальных вариантов (`o1, o2, …`), не для
   `free`/`more`.
3. Для `MORE_OPTION` («Показать ещё») — запись тоже сохранять (после раскрытия
   вопроса он остаётся answerable).
4. Входящий текст: сопоставление работает и без `reply`, пока открыт один вопрос;
   при нескольких — по `reply.mid` (как сейчас). Проверить, что после «Другой
   ответ» вопрос остаётся единственным открытым и текст находит его.
5. **Тайм-аут не «навсегда»**: если текст так и не пришёл — TTL/напоминание
   (008) снимает вопрос и возвращает его в GUI, а не держит вечно.

## Критерии готовности

- [ ] клик «Другой ответ» → сообщение в MAX просит ввести текст (тест на фейковом API);
- [ ] следующий текст в чат становится ответом (`custom`) и доходит до сессии (тест);
- [ ] запись вопроса не теряется на `free`/`more`, теряется на реальном варианте (тест);
- [ ] ответ на вопрос по `reply` тоже работает;
- [ ] нет «вечного» ожидания: TTL/напоминание срабатывают (тест);
- [ ] Telegram-путь не изменился (регресс-тест на force_reply-приглашение);
- [ ] `node --test` и `bin/ci.sh --fast` зелёные.
