## Задача

Состояние плагина должно переживать обновления.

1. `state.json`: поле `schemaVersion` (целое), строгий реестр миграций
   `{from → to: fn}` в `lib/store.js`.
2. Поведение: файл без версии = 1 (историческая); миграция вперёд по одной
   ступени; **бэкап** `state.json.bak-<version>-<ts>` перед миграцией; если
   миграция невозможна — отказ старта с внятным сообщением и инструкцией
   (`/remote doctor` показывает `fail`), никакой тихой потери данных.
3. Миграции идемпотентны и не теряют данные: например `channels` из плоского
   `chatId` в `{chatId, threadId}`.
4. Тесты: пустой файл → версия 1; файл v1 → v2 с бэкапом; неизвестная будущая
   версия → отказ (не перезапись!); повторный запуск миграции безопасен.

## Критерии готовности

- [ ] `schemaVersion` есть и проверяется на каждом чтении;
- [ ] бэкап создаётся до миграции и содержит исходный файл;
- [ ] файл из «будущего» не перезаписывается;
- [ ] повторный прогон миграций идемпотентен;
- [ ] `node --test dsh-remote/test` зелёный.
