## Задача

Сейчас политика подтверждений опасных инструментов (`bash`, `write_file`,
`git_push`, …) по умолчанию локальная — и человек узнаёт об этом только когда
подтверждение **не приходит** в мессенджер (живой случай 20.11: `bash` с
`danger-full-access` пришёл только в GUI, в чате MAX видно `approval | bash |
decision: gui`).

Управление уже есть (`/remote approvals allow|deny <tool> --force`), но:

- решение не спрашивается при подключении — то есть человек не выбирает осознанно,
  а натыкается на последствия;
- чтобы разрешить всё, надо перечислить инструменты по одному;
- нет простого «включить/выключить целиком», хотя владелец прямо говорит: «мой
  телефон всегда со мной, я хочу, чтобы подтверждения приходили туда».

## Требования

1. **Онбординг при `/remote connect`** (после вопроса о scope, перед сохранением
   привязки): один вопрос —
   «Присылать подтверждения опасных действий (запуск команд, запись файлов,
   git push) в мессенджер?»
   варианты: **Да, всё** / **Только безопасные (по умолчанию)** / **Всё только в GUI**.
   При «Да, всё» — явное предупреждение в тексте вопроса: «это разрешает
   подтверждать выполнение команд с телефона».
2. **Режим в состоянии**: `approvals.mode: "safe" | "all" | "gui-only"`.
   - `safe` — текущий дефолт (`DEFAULT_TOOLS` удалённо, `DEFAULT_DENY_REMOTE` локально);
   - `all` — всё можно подтверждать удалённо (кроме `denyRemote`, если его явно
     дополнили через `deny`), с предупреждением в `status`;
   - `gui-only` — ничего не уходит в канал (полезно, когда телефон не с собой).
3. **Команды включения/выключения**:
   - `/remote approvals mode all|safe|gui-only` — переключение без перезапуска;
   - `/remote approvals` показывает текущий режим, `tools`, `denyRemote`, `ttl` и
     последнее решение с причиной.
4. **Совместимость с 074**: точечные `allow`/`deny` продолжают работать поверх
   режима (`deny` сильнее `mode: all`).
5. **Аудит/журнал**: смена режима — событие (`approvals.mode`), предупреждение при
   `all` — в `status` и в ответе команды.
6. **Тесты**: онбординг спрашивает и сохраняет выбранный режим (три варианта);
   `mode all` реально отправляет `bash` в канал; `mode gui-only` не отправляет
   ничего даже для `read_file`; `deny` поверх `all` блокирует; `status` показывает
   режим и предупреждение; дефолт без онбординга — `safe`.

## Критерии готовности

- [ ] при `/remote connect` спрашивается режим подтверждений (один вопрос, три варианта);
- [ ] выбранный режим сохраняется и действует сразу (тест на `bash` в канале);
- [ ] `/remote approvals mode …` переключает и показывает предупреждение;
- [ ] `gui-only` полностью отключает удалённые подтверждения;
- [ ] `deny` сильнее `mode: all`;
- [ ] дефолт (без ответа) остаётся `safe`;
- [ ] `node --test` и `bin/ci.sh --fast` зелёные.
