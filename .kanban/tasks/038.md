## Задача

Правило «один канал за раз»: подключение нового транспорта отключает прежний.

1. **Состояние**: привязка остаётся одна (`state.bindings`). При `connect` нового
   транспорта:
   - сохранить имя прежнего (`previousTransport`) для сообщения человеку;
   - остановить прежний канал (поллер/WS) до сохранения новой привязки;
   - токен прежнего канала убрать из хранилища (`ctx.credentials.unset`) или, если
     хранилище только на чтение, явно сказать «токен остался в окружении»;
   - записать новую привязку.
2. **Ответчик** публикует в активный канал: если в состоянии привязка `telegram`,
   MAX-транспорт (если он поднят) не получает вопрос. Веер `broker` (012) не
   использовать в обычном режиме — только если конфиг явно просит
   `transports: [...]` с двумя и более.
3. **Сообщения**: `connect` отвечает «Telegram отключён, MAX подключён»;
   `/remote status` показывает активный канал и «прежний: telegram (отключён)».
4. **Отключение**: `/remote disconnect` чистит привязку и токен активного канала.
5. Тесты: переключение telegram→max останавливает первый поллер и не публикует в
   него; обратное переключение работает; статус показывает историю; токен прежнего
   канала удалён (или помечен, если хранилище read-only); мультиканальный режим
   включается только явным конфигом.

## Критерии готовности

- [ ] в обычном режиме вопрос уходит ровно в один канал (тест на два поднятых транспорта);
- [ ] прежний канал остановлен при переключении (тест: `stop()` вызван, подписки сняты);
- [ ] `/remote status` и ответ `connect` говорят, какой канал отключён;
- [ ] токен прежнего канала не остаётся активным;
- [ ] `node --test` и `bin/ci.sh --fast` зелёные.
