## Задача

Очередь подтверждений: их бывает несколько одновременно.

1. Несколько `approval/request` из разных сессий и разных инструментов: очередь,
   нумерация, маркировка воркспейс/сессия/задача, отдельные `callId`.
2. Роутинг ответа: кнопка → свой `callId`; свободный текст в подтверждениях
   **не** считается ответом (в отличие от вопросов) — только кнопка, иначе
   просим нажать.
3. Ответ на уже закрытое подтверждение (таймаут/аборт/решено в GUI) не меняет
   исход, а логируется.
4. Тесты: два подтверждения параллельно → решения независимы; ответ «не тот»
   callId игнорируется; текст вместо кнопки → подсказка и повтор; закрытие
   проигравшего канала (мультиканальность из 012) работает и здесь.

## Критерии готовности

- [ ] решения не путаются между callId (тест на два одновременных);
- [ ] свободный текст не подменяет решение;
- [ ] повторный ответ не переигрывает исход;
- [ ] `node --test dsh-remote/test` зелёный.
