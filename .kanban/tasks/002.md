## Задача

Домен вопросов и ответчик waterfall'а — сердце системы.

1. `dsh-remote/lib/domain/question.js`: модель `RemoteQuestion`
   (`id` uuid, `shortId` — 8 hex, `sessionId`, `workspace`, `role?`, `taskId?`,
   `title?`, `body`, `options[{id,label}]`, `multiSelect`, `allowFreeText`,
   `createdAt`, `expiresAt`, `status: pending|open|answered|expired|cancelled`,
   `answer?{selected,custom}`, `answeredBy?`), конструктор из элемента
   `AskUserQuestionItem` и метод `toAnswer()` → `{id, selected, custom?}`
   (см. `packages/interaction/user-questions/src/types.ts`). Переход
   `open → answered` ровно один раз (повтор — no-op + лог).
2. `dsh-remote/lib/domain/registry.js`: включён ли удалённый режим для scope
   (`global` / воркспейс по `cwd` / сессия), с приоритетом «сессия → воркспейс → глобально».
   Источник данных инжектируется (реальное хранилище появится в 005).
3. `dsh-remote/lib/answerer.js`: `createAnswerer({ transport, registry, log, now })` →
   `{ attach(ctx), handler }`. Регистрирует
   `ctx.on('user-questions/request', handler, { prepend: true })` — **`prepend`
   обязателен**: мост `api-remotes`, отдающий вопрос браузеру, регистрируется
   раньше любого плагина, и без `prepend` наш слушатель вызовется только после
   `next()` из браузера (см. `docs/research/dsh-hooks.md` §2.2). Waterfall-контракт:
   `(request, next) => Promise<AskUserQuestionAnswer>`:
   - режим выключен → `return next()` (поведение DSH не меняется);
   - включён → создать вопросы, `transport.sendQuestion`, ждать ответ без таймаута
     (TTL — в 008), вернуть `{answers: [...]}`;
   - `request.signal` абортится → сообщение закрывается (`closeQuestion`), промис
     отклоняется так, чтобы DSH получил `ASK_ABORTED`-семантику (не глотать ошибку);
   - несколько вопросов в одном запросе поддерживаются (их бывает `questions[]`).
4. Подключить фичу в `lib/features.js` **одной строкой** (файл `index.js` не переписывать).
5. `docs/research/waterfall-order.md`: короткий отчёт (20–40 строк) о порядке
   ответчиков в waterfall `user-questions/request` — кто регистрируется раньше,
   что будет, если GUI-ответчик зарегистрируется первым, можно ли вернуть вопрос
   в GUI через `next()` после отправки в мессенджер. Проверить по исходникам
   (`packages/core/scope`, `packages/client/ui-user-questions`) и подтвердить тестом.
6. Тесты `dsh-remote/test/answerer.spec.js` и `test/question.spec.js` на фейковом
   `ctx`/транспорте: выключенный режим → `next()` вызван; ответ кнопкой → `selected`;
   `custom` → свободный текст; `multiSelect`; аборт сигнала → `cancelled` +
   `closeQuestion`; два одновременных вопроса не путаются.

- [ ] фича подключена одной строкой в `lib/features.js`.

## Заметки

- **Не звать `next()`, когда вопрос забрали**: тогда remote-событие не создаётся
  (`docs/research/dsh-hooks.md` §2.3). Обратный сценарий — «позвать `next()` и
  ответить раньше браузера» — оставляет висящую панель в GUI, так не делать.
- Точка входа: `packages/interaction/user-questions/src/index.ts:136` (waterfall),
  `packages/interaction/tool-ask-user/src/index.ts` (форма вопроса),
  `packages/client/ui-user-questions/src/client/index.ts:104` (GUI-ответчик).
- Не отправляй вопрос, если `request.questions.length === 0` — это ошибка ядра, не наша.
- `agent.id` — это `SessionId`; шапка сессии (`ctx.sessions.get(id)`) даст `cwd` и
  `agentPreset` — но маркировка это задача 006, здесь только поля в модели.

- Концепция — `docs/CONCEPT.md` (разделы 3–8), спека — `.kanban/specs/001.md`.
- Каталог задачи — `worktrees/<id>` (ветка `task/<id>`). Сессия роли живёт в корне
  проекта, поэтому **работать только внутри `worktrees/<id>`**: `cd worktrees/<id>`,
  дальше всё относительно него; в корне и в чужих `worktrees/*` не писать.
- Общие файлы не трогать: `AGENTS.md`, `.kanban/` (кроме своей карточки), `bin/task-*.sh`.
- Профиль DSH (`~/.dsh/profiles`) в этой задаче не правится — установку делает человек/оркестратор.
- Язык: JS (ESM), только `node:` builtins; тесты — `node --test` (если `node` не в PATH — `bin/node.sh`).
- Все git-команды и `bin/task-move.sh` — из каталога задачи (`cd worktrees/002`);
  основную ветку и карточки других задач не трогать.
- Сдача: `cd worktrees/002 && bin/task-move.sh 002 in-review --role worker --tokens auto --note "..."`.
