## Задача

Установщик, документация и `/remote doctor` — чтобы системой можно было пользоваться.

1. `bin/install-remote.sh` — по образцу `~/projects/dsh-kanban/bin/install-kanban.sh`
   (только чтение образца): `--profile web|desktop`, `--dry-run` (печатает план,
   ничего не меняет), идемпотентность, отказ при двойном ряде. **Не запускать самому
   из песочницы**: установка в профиль — шаг человека/оркестратора, скрипт лишь
   готовит и проверяет.
2. `/remote doctor` (доработка `lib/commands.js` — аккуратно, файл из 005):
   проверка ссылки на токен, `getMe`, конфликт поллеров (lock), задержка последнего
   апдейта, состояние `state.json`, права файла, версия плагина. Вывод — список
   пунктов `ok/warn/fail` и что делать дальше.
3. `docs/user-guide.md`: как завести бота у @BotFather (пошагово, скриншоты словами),
   что нажать, где взять `chat_id`, как подключить (`/remote connect`), как выключить,
   что происходит при недоступности мессенджера, безопасность и allowlist, FAQ
   (не приходят вопросы / «часики» на кнопке / 409 Conflict / MAX не подключается).
4. `README.md` в корне проекта: что это за система, из чего состоит (плагин, мост,
   канбан), быстрый старт, ссылки на `docs/CONCEPT.md`, `.kanban/specs/001.md`,
   `AGENTS.md`, структура репозитория.
5. Тесты: `test/install-script.spec.js` — `bash -n` и `--dry-run` печатает план и
   ничего не пишет; `test/doctor.spec.js` — форматирование отчёта на фейковых
   сервисах (все ok / есть fail).

## Критерии готовности

- [ ] `bin/install-remote.sh --dry-run` печатает план и не трогает `~/.dsh`;
- [ ] `bash -n bin/install-remote.sh` и `shellcheck`-уровень чистоты (если есть shellcheck);
- [ ] `docs/user-guide.md` позволяет человеку пройти путь «бот → подключение → вопрос» без кода;
- [ ] `README.md` объясняет систему и ведёт по ссылкам;
- [ ] `/remote doctor` даёт actionable-вывод;
- [ ] `node --test dsh-remote/test` — зелёный;
- [ ] `AGENTS.md` не правится (это общий файл оркестратора): если нужен раздел — опиши
      его в карточке заметкой, вольёт оркестратор.

## Заметки

- Образцы: `~/projects/dsh-kanban/bin/install-kanban.sh`, `README.md`, `KANBAN.md` (только чтение).
- Документация на русском, как остальные документы проекта.
- Профиль DSH общий с другими проектами: установщик обязан быть идемпотентным и
  ничего не ломать, а `--dry-run` — безопасным по умолчанию.

- Концепция — `docs/CONCEPT.md` (разделы 3–8), спека — `.kanban/specs/001.md`.
- Каталог задачи — `worktrees/<id>` (ветка `task/<id>`). Сессия роли живёт в корне
  проекта, поэтому **работать только внутри `worktrees/<id>`**: `cd worktrees/<id>`,
  дальше всё относительно него; в корне и в чужих `worktrees/*` не писать.
- Общие файлы не трогать: `AGENTS.md`, `.kanban/` (кроме своей карточки), `bin/task-*.sh`.
- Профиль DSH (`~/.dsh/profiles`) в этой задаче не правится — установку делает человек/оркестратор.
- Язык: JS (ESM), только `node:` builtins; тесты — `node --test` (если `node` не в PATH — `bin/node.sh`).
- Все git-команды и `bin/task-move.sh` — из каталога задачи (`cd worktrees/010`);
  основную ветку и карточки других задач не трогать.
- Сдача: `cd worktrees/010 && bin/task-move.sh 010 in-review --role worker --tokens auto --note "..."`.
