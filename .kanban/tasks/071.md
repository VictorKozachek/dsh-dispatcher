## Задача

Живая приёмка зеркала в режиме `notify` (2026-11-18, 20:26, канал MAX):

- вопрос пришёл в MAX и одновременно появился в GUI — **это работает**;
- ответ дан **в GUI** → результат вернулся в сессию (инструмент получил ответ);
- **но сообщение в MAX осталось висеть с кнопками** и не сменилось на
  «✅ Отвечено в GUI». В журнале: `question.mirror.published {mode:"notify"}`,
  дальше — ничего (нет `answer.from_gui`, нет закрытия).

Ожидание по документации (`docs/user-guide.md §5.1`, `#067`): после ответа в GUI
сообщение в мессенджере гасится/помечается, кнопки снимаются.

## Причина (по коду)

`lib/answerer.js`, ветка публикации:

```js
if (answered === HYBRID_GUI || guiRequested) {
  cleanupHybrid();
  return next();            // ← владение уходит в GUI, и мы больше ничего не делаем
}
```

`next()` возвращает ответ GUI, но код **не дожидается** его и ничего не закрывает:
сообщение в канале остаётся с кнопками до TTL. Ветка «GUI ответил первым → гасим
сообщения» есть только для `mirrorFull` (там `mirrorGuiPromise` в гонке), а для
`mode: "notify"` её нет.

Дополнительно: клик по кнопке в MAX после ответа в GUI обрабатывается как
«вопрос закрыт» и попадает в `answer.unmatched`/`dropped` — но сообщение об этом
человеку не говорит.

## Требования

1. В `notify`-режиме: `const result = await next();` затем **закрыть сообщения**
   каналов (`closeQuestions(questions, "answered-in-gui")`), отредактировав текст в
   «✅ Отвечено в GUI» и сняв кнопки, и только потом вернуть `result`.
2. Ошибка закрытия не должна ломать ответ: сессия получает результат даже если
   `editQuestion`/`closeQuestion` упали (ошибка — в журнал, ответ — в сессию).
3. `answer.from_gui` в журнале с `mode: "notify"` и списком каналов.
4. Клик по кнопке в канале после ответа в GUI → `answer.dropped {reason:"gui"}`,
   и человеку короткая подсказка «ответ уже дан в GUI» (одним сообщением/правкой
   строки, без спама).
5. Аборт/TTL в `notify` — как сейчас (оба представления закрываются).
6. Тесты: `next()` вернул ответ → сообщение закрыто, кнопки сняты; `closeQuestion`
   бросает → ответ всё равно возвращён, в журнале ошибка; поздний клик →
   `dropped("gui")` без `unmatched`; `full`-режим не сломан.

## Критерии готовности

- [ ] в `notify` после ответа в GUI сообщение в MAX/Telegram гасится (тест + живьём);
- [ ] ответ в сессию не зависит от успеха закрытия сообщения (тест);
- [ ] `answer.from_gui` пишется в журнал (тест);
- [ ] поздний клик — `dropped`, а не `unmatched` (тест);
- [ ] `full`-режим и `remote-only` не изменились (регресс);
- [ ] `node --test` и `bin/ci.sh --fast` зелёные.
