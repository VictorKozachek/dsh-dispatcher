## Задача

Разложить вопросы по проектам, чтобы разные воркспейсы не смешивались.

1. В `store`: карта `channels: { "<basename cwd>": { chatId, threadId? } }` и
   глобальный `defaultChatId`; `resolveChannel(workspace)` → chat/thread.
2. Команда `/remote channel <имя> <chatId> [threadId]` и `/remote channel list`;
   в Telegram `threadId` — `message_thread_id` (топики форумов), в MAX — аналог
   или отдельный чат.
3. Отправка вопроса/уведомления идёт в канал проекта; если канала нет — в общий,
   и в шапке это видно (уже есть маркировка из 006).
4. Если у проекта отдельный чат — allowlist проверяется и для него; привязка
   кода pairing тоже привязывается к каналу.
5. Тесты: маршрутизация по воркспейсу, fallback на общий чат, `channel list`,
   отказ для чужого chatId, вопросы двух проектов не путаются.

## Критерии готовности

- [ ] `resolveChannel` покрыт тестами (есть канал/нет/чужой);
- [ ] `/remote channel` не ломает существующую привязку и секреты;
- [ ] в `/remote status` видно, какой канал у какого проекта;
- [ ] `node --test dsh-remote/test` зелёный.
