## Задача

Telegram-транспорт — первый рабочий канал.

1. `dsh-remote/lib/transport/telegram.js`: реализация контракта из 003.
   - `start()`: long polling `getUpdates` (`timeout` 25–50 с, `allowed_updates`
     `["message","callback_query"]`), `offset = update_id + 1` после обработки,
     `AbortController` для остановки, экспоненциальный backoff при сетевых ошибках,
     `retry_after` при 429, `409 Conflict` — внятная ошибка «второй поллер на тот же токен»;
   - `sendQuestion`: `sendMessage` (`parse_mode: HTML`, кнопки — `inline_keyboard`,
     по одной на строку, `reply_markup` строится из `q.options` через хелперы 003);
   - `closeQuestion`: `editMessageText` (или `editMessageReplyMarkup` при пустом
     тексте) → «✅ Отвечено: …», кнопки сняты; ошибка правки не должна ломать ответ;
   - входящее: `callback_query` → сразу `answerCallbackQuery` (иначе «часики»),
     затем событие в `onAnswer`; `message` → свободный текст (в `onAnswer` как `text`);
   - allowlist: `from.id` и `chat.id` сверяются с привязкой, всё чужое — лог и игнор;
   - `healthCheck`: `getMe` + состояние цикла (последний `update_id`, время последнего апдейта).
2. Тесты `dsh-remote/test/telegram.spec.js` на **фейковом `fetch`** (инжектируется):
   отправка вопроса → нажатие кнопки → ответ; 429 c `retry_after` → повтор;
   повторный `update_id` игнорируется; чужая `chat_id`/`from.id` игнорируются;
   `409` → понятная ошибка; `stop()` прекращает цикл (таймеры не текут).
3. `dsh-remote/lib/features.js`: фича `telegram` — одна строка; старт/стоп по
   команде/состоянию (если транспорта нет в конфиге — фича спит).
