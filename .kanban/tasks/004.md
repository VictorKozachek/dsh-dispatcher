## Задача

Telegram-транспорт — первый рабочий канал.

1. `dsh-remote/lib/transport/telegram.js`: реализация контракта из 003.
   - `start()`: long polling `getUpdates` (`timeout` 25–50 с, `allowed_updates`
     `["message","callback_query"]`), `offset = update_id + 1` после обработки,
     `AbortController` для остановки, экспоненциальный backoff при сетевых ошибках,
     `retry_after` при 429, `409 Conflict` — внятная ошибка «второй поллер на тот же токен»;
   - `sendQuestion`: `sendMessage` (`parse_mode: HTML`, кнопки — `inline_keyboard`,
     по одной на строку, `reply_markup` строится из `q.options` через хелперы 003);
   - `closeQuestion`: `editMessageText` (или `editMessageReplyMarkup` при пустом
     тексте) → «✅ Отвечено: …», кнопки сняты; ошибка правки не должна ломать ответ;
   - входящее: `callback_query` → сразу `answerCallbackQuery` (иначе «часики»),
     затем событие в `onAnswer`; `message` → свободный текст (в `onAnswer` как `text`);
   - allowlist: `from.id` и `chat.id` сверяются с привязкой, всё чужое — лог и игнор;
   - `healthCheck`: `getMe` + состояние цикла (последний `update_id`, время последнего апдейта).
2. Тесты `dsh-remote/test/telegram.spec.js` на **фейковом `fetch`** (инжектируется):
   отправка вопроса → нажатие кнопки → ответ; 429 c `retry_after` → повтор;
   повторный `update_id` игнорируется; чужая `chat_id`/`from.id` игнорируются;
   `409` → понятная ошибка; `stop()` прекращает цикл (таймеры не текут).
3. `dsh-remote/lib/features.js`: фича `telegram` — одна строка; старт/стоп по
   команде/состоянию (если транспорта нет в конфиге — фича спит).

## Критерии готовности

- [ ] реализация соответствует контракту 003 и проходит его тесты;
- [ ] `client_data`/`callback_data` кодируются через общие хелперы, не руками;
- [ ] дедуп и `offset` переживают перезапуск (персист — через инжектируемый колбэк);
- [ ] 429/сеть/409 покрыты тестами и не валят процесс;
- [ ] `node --test dsh-remote/test` — зелёный, без реальной сети;
- [ ] `docs/research/messengers.md` §1 использован как источник лимитов и полей API.

## Заметки

- Никакого `node-fetch`: в Node 24+ есть глобальный `fetch`; его и инжектировать.
- Токен приходит из хранилища (005), в этой задаче — параметр конструктора.
- Тело вопроса и кнопки не содержат секретов: маскирование — задача 008.

- Концепция — `docs/CONCEPT.md` (разделы 3–8), спека — `.kanban/specs/001.md`.
- Каталог задачи — `worktrees/<id>` (ветка `task/<id>`). Сессия роли живёт в корне
  проекта, поэтому **работать только внутри `worktrees/<id>`**: `cd worktrees/<id>`,
  дальше всё относительно него; в корне и в чужих `worktrees/*` не писать.
- Общие файлы не трогать: `AGENTS.md`, `.kanban/` (кроме своей карточки), `bin/task-*.sh`.
- Профиль DSH (`~/.dsh/profiles`) в этой задаче не правится — установку делает человек/оркестратор.
- Язык: JS (ESM), только `node:` builtins; тесты — `node --test` (если `node` не в PATH — `bin/node.sh`).
- Все git-команды и `bin/task-move.sh` — из каталога задачи (`cd worktrees/004`);
  основную ветку и карточки других задач не трогать.
- Сдача: `cd worktrees/004 && bin/task-move.sh 004 in-review --role worker --tokens auto --note "..."`.
