## Задача

Журнал (`~/.dsh/remote-control/log.jsonl`) пишет события без привязки к
**воркспейсу и сессии**, поэтому:

- нельзя понять, из какого проекта пришёл вопрос (панель истории не может
  фильтровать — фильтр снят из `#070`);
- при разборе «вопрос из другой сессии не дошёл» приходится гадать (ровно это
  случилось 20.11: события `question.skipped` покажут причину, но не скажут
  «из какого воркспейса»);
- аудит/метрики по проектам невозможно посчитать по журналу.

## Требования

1. В каждое событие журнала добавлять **контекст выполнения** (там, где он есть):
   - `sessionId` — маскированный (8 символов уникальной части, как в `#069`);
   - `workspace` — basename проекта (полный путь не писать, это персональные данные);
   - `preset`/`role` — если известны.
2. Контекст определяется **один раз на запрос** (не на каждое событие пачки) и
   подставляется в события `question.send/sent/error/skipped/closed`,
   `answer.received/from_transport/from_gui/dropped/unmatched`, `context.resolve`,
   `question.mirror.published`, `pairing.*`.
3. Обратная совместимость: старые строки без полей читаются как раньше (панель,
   `journal-read`, тесты не падают).
4. **Приватность**: никаких полных путей и имён пользователя; только basename;
   токены и тексты ответов — как сейчас, не пишутся.
5. Панель истории (`#070`): вернуть фильтр по проекту — теперь он работает на
   реальных данных (по `workspace` в событии), плюс тест на фикстуре с двумя
   проектами.
6. Тесты: событие содержит `sessionId`/`workspace`; старые строки без полей
   читаются; фильтр в панели действительно отбирает по проекту; приватность
   (нет полных путей).

## Критерии готовности

- [ ] события журнала содержат маскированные `sessionId`/`workspace`/`preset` (тест);
- [ ] старые записи журнала читаются без ошибок (тест);
- [ ] фильтр по проекту в панели истории работает на реальных данных (тест);
- [ ] полных путей и текстов ответов в журнале нет (тест);
- [ ] `node --test` и `bin/ci.sh --fast` зелёные.
