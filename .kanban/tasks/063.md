## Задача

Реализовать режим `mirror` с **определением возможностей хоста**: если хост даёт
`settle`/`cancel` и событие «отвечено» — полное зеркало (первый ответ побеждает);
если нет — деградация B (GUI — источник истины, мессенджер — уведомление).

## Требования

1. **Feature-detect** при `apply`: `service.settle instanceof Function`,
   наличие события `user-questions/resolved` (или того, что предложит 062).
   Результат — `caps.mirror = 'full' | 'notify' | 'none'`.
2. **Полный mirror** (`full`):
   - вопрос публикуется в канал **и** отдаётся в GUI (`next()`);
   - ответ из канала → `settle(callId, answer)`, инструмент получает этот ответ;
   - ответ из GUI (событие `resolved`, `source: 'gui'`) → сообщение в канале
     гасится «✅ Отвечено в GUI» (без текста ответа, если он секретный);
   - поздний ответ из канала после `settle` → `answer.dropped` в журнал, без
     `steer` и без второго результата.
3. **Деградация B** (`notify`): как описано в 059 — GUI источник истины,
   мессенджер только уведомляет; клик по кнопке даёт подсказку «ответьте в GUI»,
   но не ответ инструмента.
4. **`/remote mirror on|off`** и `status`: показывать `mirror: full|notify|none` и
   причину (`хост не даёт settle`).
5. **Журнал**: `question.mirror.published {targets}`, `answer.from_gui`,
   `answer.from_transport`, `answer.settled`, `answer.dropped {reason}`.
6. **Совместимость**: `remote-only` по умолчанию, `hybrid` (013) не ломается.
7. **Тесты** (фейковый хост-сервис с settle/cancel и без):
   - `full`: ответ из канала → `settle` вызван один раз, результат — ответ;
   - `full`: ответ GUI → сообщение закрыто, поздний клик отброшен;
   - `full`: гонка → ровно один `settle`, второй ответ `dropped`;
   - `notify`: клик в канале не завершает tool-call, подсказка отправлена;
   - аборт/TTL снимают оба представления;
   - `status` и `/remote mirror` в обоих режимах.

## Критерии готовности

- [ ] режим определяется автоматически по возможностям хоста (тест);
- [ ] полный mirror работает с фейковым `settle` (тест на первый ответ и гонку);
- [ ] без `settle` — деградация B, tool-call не завершается кликом (тест);
- [ ] аборт/TTL чистят `pending` и оба представления (тест);
- [ ] `status`/`/remote mirror` показывают режим и причину;
- [ ] `node --test` и `bin/ci.sh --fast` зелёные.

## Заметки

- Зависит от 062 (что именно даёт хост) и 059 (план B).
- Не менять поведение `remote-only`; `mirror` включается явно.
- Аккуратно с `broker` (012) и `hybrid` (013).
