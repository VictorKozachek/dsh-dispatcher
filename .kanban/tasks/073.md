## Задача

Владелец хочет полное зеркало: «ответил в MAX — пропало в GUI, ответил в GUI —
пропало в MAX». Аудит `#058` показал, что **вторая половина** (снять живой вопрос из
GUI) без правки хоста невозможна: у `UserQuestionService` нет `settle/cancel`,
а карточка в браузере удаляется только когда проекция `userQuestions` не содержит
call.

Что **достижимо уже сейчас** и что делает этот срез:

1. **GUI → MAX** (уже в `#071`): ответ в GUI гасит сообщение в канале.
2. **MAX → сессия** (эта карточка): ответ из канала в режиме `notify` **не
   теряется**. Сейчас он отбрасывается (`answer.dropped {reason:"notify"}`), хотя
   человек его дал. Нужно доставить его в сессию как `steer`-сообщение
   (`sessionController.prompt`, режим `steer` — этот механизм уже используется
   гибридом/поздними ответами, см. `steerLateAnswer`), и погасить сообщение канала
   «✅ Отвечено».
3. **GUI-карточка после ответа из канала**: снять её нельзя (ограничение хоста).
   Она остаётся, но становится безвредной: мы помечаем вопрос закрытым и
   игнорируем поздний GUI-ответ как дубль (`answer.dropped {reason:"answered-in-
   messenger"}`), чтобы он не перетёр результат.
4. В сообщении канала после ответа — текст «✅ Отвечено (передано в сессию)».

## Требования

1. `notify` + ответ из канала → `steer` ответа в сессию **один раз**; повторный
   клик не стеерит второй раз (`dropped`).
2. Журнал: `answer.from_transport {mode:"notify", delivered:"steer"}`, затем
   `question.closed {reason:"answered-in-messenger"}`; ошибка `prompt` — `steer`
   не удался → честная запись и сообщение человеку «не доставлено, ответьте в GUI».
3. Если сессия уже ответила в GUI — поздний ответ канала не стеерит (дубль).
4. `full`-режим не меняется (там `settle`). `remote-only` не меняется (там ответ
   канала — обычный путь).
5. Тесты: `notify` + канал → `prompt(steer)` вызван один раз, сообщение закрыто;
   второй клик — `dropped`; GUI уже ответил → `dropped`; ошибка `prompt` → журнал
   + закрытие сообщения без «✅»; `full`/`remote-only` регресс.

## Критерии готовности

- [ ] в `notify` ответ из мессенджера доезжает до сессии steer-ом (тест);
- [ ] повторный ответ не дублирует steer (тест);
- [ ] журнал отражает путь ответа (`delivered:"steer"`) (тест);
- [ ] `full` и `remote-only` не изменились (регресс);
- [ ] `node --test` и `bin/ci.sh --fast` зелёные.
