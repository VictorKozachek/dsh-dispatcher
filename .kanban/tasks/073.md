## Задача

Владелец хочет полное зеркало: «ответил в MAX — пропало в GUI, ответил в GUI —
пропало в MAX». Аудит `#058` показал, что **вторая половина** (снять живой вопрос из
GUI) без правки хоста невозможна: у `UserQuestionService` нет `settle/cancel`,
а карточка в браузере удаляется только когда проекция `userQuestions` не содержит
call.

Что **достижимо уже сейчас** и что делает этот срез:

1. **GUI → MAX** (уже в `#071`): ответ в GUI гасит сообщение в канале.
2. **MAX → сессия** (эта карточка): ответ из канала в режиме `notify` **не
   теряется**. Сейчас он отбрасывается (`answer.dropped {reason:"notify"}`), хотя
   человек его дал. Нужно доставить его в сессию как `steer`-сообщение
   (`sessionController.prompt`, режим `steer` — этот механизм уже используется
   гибридом/поздними ответами, см. `steerLateAnswer`), и погасить сообщение канала
   «✅ Отвечено».
3. **GUI-карточка после ответа из канала**: снять её нельзя (ограничение хоста).
   Она остаётся, но становится безвредной: мы помечаем вопрос закрытым и
   игнорируем поздний GUI-ответ как дубль (`answer.dropped {reason:"answered-in-
   messenger"}`), чтобы он не перетёр результат.
4. В сообщении канала после ответа — текст «✅ Отвечено (передано в сессию)».

## Ключевое уточнение (19.11, от владельца)

Владелец справедливо заметил: «если ответил в MAX, а плашка в GUI не пропадает —
сессия повиснет». Это верно для текущего `notify`: он **отбрасывает** ответ канала и
продолжает ждать GUI.

Правильное решение — **не отбрасывать, а завершить инструмент ответом из канала**:

```js
const guiAnswer = next();                       // показали карточку в GUI
const winner = await Promise.race([guiAnswer, transportAnswer]);  // кто первый
return winner;                                  // инструмент завершается ЛЮБЫМ ответом
```

Следствия:
- сессия **не висит**: как только ответил в MAX, tool-call завершается этим ответом;
- сообщение в MAX гасится «✅ Отвечено»;
- плашка в GUI остаётся видимой (снять её из плагина нельзя — аудит `#058`), но она
  уже **безвредна**: `guiAnswer` больше никто не ждёт; когда человек нажмёт в GUI,
  карточка просто закроется, а ответ будет проигнорирован как дубль
  (`answer.dropped {reason:"already-answered"}`);
- если первым ответил GUI — его ответ возвращается, а сообщение в MAX гасится
  (это `#071`).

То есть полная симметрия по **результату** достигается уже сейчас; не достигается
только визуальное исчезновение GUI-плашки без действия человека — это остаётся до
появления `settle/cancel` в хосте.

## Требования

1. `notify` + ответ из канала → **инструмент завершается этим ответом** (гонка
   `next()` против ответа транспорта), ровно один раз; повторный клик не меняет
   результат (`dropped`). `steer` использовать **не надо** — он не завершает
   tool-call и как раз оставлял бы сессию ждать.
2. Журнал: `answer.from_transport {mode:"notify", delivered:"tool-result"}`, затем
   `question.closed {reason:"answered-in-messenger"}`; если гонку выиграл GUI —
   `answer.from_gui` и закрытие сообщения в канале.
3. Если сессия уже ответила в GUI — поздний ответ канала не стеерит (дубль).
4. `full`-режим не меняется (там `settle`). `remote-only` не меняется (там ответ
   канала — обычный путь).
5. Тесты: `notify` + ответ канала → инструмент вернул ответ, сообщение закрыто,
   `guiAnswer` не ждёт; второй клик — `dropped`; ответ GUI первым → его результат и
   закрытие канала; гонка «почти одновременно» → ровно один результат; поздний
   ответ GUI после ответа канала → `dropped {reason:"already-answered"}`;
   аборт → оба представления закрыты; `full`/`remote-only` регресс.

## Критерии готовности

- [ ] в `notify` ответ из мессенджера **завершает инструмент** (сессия не висит) — тест;
- [ ] повторный/поздний ответ не меняет результат (тест);
- [ ] журнал отражает путь ответа (`delivered:"tool-result"`; steer не используется по ключевому уточнению) (тест);
- [ ] `full` и `remote-only` не изменились (регресс);
- [ ] `node --test` и `bin/ci.sh --fast` зелёные.
