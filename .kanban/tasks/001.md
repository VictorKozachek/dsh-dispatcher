## Задача

Поднять каркас плагина `dsh-remote` — пакета DSH в этом репозитории, без логики.

1. Каталог `dsh-remote/` — пакет плагина (ESM, `type: module`, зависимости только `@deepseek-ai/cordis` как peer).
2. `dsh-remote/package.json`:
   - `name: "dsh-remote"`, `version: "0.1.0"`, `private: true`, `license: "MIT"`;
   - `main: "lib/index.js"`, `exports`: `"."`, `"./cordis.patch.yml"`, `"./package.json"`
     (`"./client"` добавит задача 009, не сейчас);
   - `files: ["lib", "cordis.patch.yml"]`;
   - `dsh.bundle.patch: "./cordis.patch.yml"`;
   - `peerDependencies: { "@deepseek-ai/cordis": "^4.0.2" }`.
3. `dsh-remote/cordis.patch.yml` — один `insert`-ряд: `id: ui-remote`, `name: 'dsh-remote'`,
   `config: {}` и комментарии (что это, как включить, где состояние).
4. `dsh-remote/lib/index.js` — `export const name`, `export const inject` (пока `[]`),
   `export function apply(ctx, config)`; apply читает config, создаёт `ctx`-логгер
   (`[dsh-remote]`) и прогоняет список фич из `lib/features.js`. Плагин обязан
   деградировать, а не падать: если сервиса в `ctx` нет — пишет `warn` и работает дальше.
5. `dsh-remote/lib/features.js` — реестр `export const features = []` с комментарием
   «сюда добавляются фичи одной строкой; каждая — `{ name, apply(ctx, config, deps) }`».
   Так следующие задачи подключаются одной строкой и не конфликтуют в `index.js`.
6. `dsh-remote/README.md` — 15–25 строк: что это, как включается, где лежит состояние,
   ссылка на `docs/CONCEPT.md`.
7. Тест `dsh-remote/test/plugin.spec.js`: импорт пакета, `apply` на фейковом `ctx`
   (объект с `get`, `on`, `logger`) без сервисов — не падает; список фич пуст;
   `cordis.patch.yml` содержит ровно один ряд `ui-remote` и `name: 'dsh-remote'`.
