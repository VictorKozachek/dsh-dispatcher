## Задача

Поведение в неудобных случаях: недоставка, рестарт, TTL, секреты в теле.

1. `dsh-remote/lib/reliability.js`:
   - очередь недоставленных (`pending`) с повтором и экспоненциальным backoff,
     `retry_after` уважаем; после `connectTimeoutMs` (30 с) вопрос отдаётся GUI —
     ответчик из 002 должен вернуть `next()` (согласовать точку вызова);
   - старт плагина: «осиротевшие» вопросы из `state.json` → `cancelled`,
     сообщения правятся «сессия перезапущена, вопрос снят» (best-effort, ошибки не валят старт);
   - TTL-сторож (`setInterval`, `unref`, инжектируемые часы): напоминание правкой за
     5 мин до истечения, по истечении — `expired`, кнопки сняты, повторный пуш
     не чаще 30 мин. **Важно:** таймаута на вопрос в DSH нет, а после публикации
     вопроса звать `next()` уже нельзя (висящая панель). Поэтому у истечения
     ровно три исхода, один обязателен в конфиге: `onExpire: 'abort'` (по
     умолчанию — `ASK_ABORTED`), `'empty'` (`selected: []`, `custom: "(нет ответа)"`)
     или `'default-first'` (первый вариант);
   - поздний ответ: если вопрос ещё открыт — применить; если снят — доставить в
     сессию `sessionController.prompt` с `mode: 'steer'` (это единственный путь
     вернуть ответ в уже опубликованный вопрос, см. `docs/research/dsh-hooks.md` §9.4);
   - `redact(text)`: маска для `bot\d+:…`, `sk-…`, `BEGIN … PRIVATE KEY`, длинных
     base64-подобных строк; `redactMode: 'warn' | 'strict'` (`strict` — тело не
     отправляется, в сообщении «вопрос скрыт»);
   - журнал `~/.dsh/remote-control/log.jsonl` (без токенов и тел вопросов по умолчанию,
     ротация по размеру), `healthCheck()` для `doctor`.
2. Тесты `test/reliability.spec.js` на фейковых часах и фейковом транспорте:
   недоставка → повтор → отдача в GUI; рестарт с открытым вопросом → `cancelled` +
   правка сообщения; TTL → напоминание → `expired`; `default-first` отвечает первым вариантом;
   redact ловит токены и не портит обычный текст; журнал не содержит секретов.

## Критерии готовности

- [ ] ни один путь отказа не оставляет сессию в вечном ожидании без сообщения человеку;
- [ ] рестарт не «оживляет» мёртвые вопросы и не спамит в чат;
- [ ] TTL-политика соответствует `docs/CONCEPT.md` §7.3;

- [ ] `node --test dsh-remote/test` — зелёный, тесты быстрые (без реальных задержек).

  того как вопрос ушёл браузеру, отменить его из плагина нельзя (`dsh-hooks.md` §2.3).

- Язык: JS (ESM), только `node:` builtins; тесты — `node --test` (если `node` не в PATH — `bin/node.sh`).
- Все git-команды и `bin/task-move.sh` — из каталога задачи (`cd worktrees/008`);
  основную ветку и карточки других задач не трогать.
