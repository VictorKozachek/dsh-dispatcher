## Задача

Подтверждения действий (`approval/request`) приходят в MAX, но в шапке —
**пресет** (`standard`) вместо имени сессии. То же самое чинили для вопросов в
`#078`; у подтверждений свой путь сборки контекста, и там имя не передаётся.

## Причина (точная)

`dsh-remote/lib/approvals.js`, `marksOf(sessionId)`:

```js
const resolved = resolveContextHot({ sessionId, ctx: context, log });
return { role: resolved?.role ?? null, taskId: resolved?.taskId ?? null };
// sessionTitle / branch / worktree — не возвращаются
```

Дальше `new RemoteApproval(request, { sessionId, workspace, role: marks.role,
taskId: marks.taskId, … })` — то есть `sessionTitle` не доходит ни до модели, ни до
рендера. `renderHeader` в этом случае печатает `agentPreset` = `standard`.

Проверено вживую 20.11 19:40: подтверждение `bash` ушло в MAX
(`audit: approval | bash | decision: remote | outcome: allowed-once`), а в шапке
сообщения — `standard`.

## Требования

1. `marksOf` возвращает **весь контекст**: `role`, `sessionTitle`, `taskId`,
   `branch`, `worktree` (передавать объект, а не перечисление — как сделано в
   `#078` для вопросов: `...resolved`).
2. `RemoteApproval` принимает и хранит `sessionTitle`; рендер подтверждения
   использует его так же, как вопросы (`displayRole` → имя, иначе пресет).
3. Тест на **payload**: подтверждение уходит в канал, и в шапке отправленного текста
   есть имя сессии (фейковый `sessions.get` с `agentPreset: "standard"` +
   `session_projcache` с `title.val: "Оркестратор"`), а не `standard`.
4. Регресс: без имени — прежний пресет; `#078` для вопросов не ломается.

## Критерии готовности

- [ ] шапка подтверждения содержит имя сессии (тест на payload);
- [ ] без имени — пресет (тест);
- [ ] поля контекста передаются через `...resolved`, а не списком;
- [ ] `node --test` и `bin/ci.sh --fast` зелёные;
- [ ] живая проверка: подтверждение в MAX с именем сессии.
