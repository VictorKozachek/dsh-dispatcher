## Задача

Один вопрос — два канала одновременно, первый ответ побеждает.

1. `dsh-remote/lib/broker.js` (или расширение `answerer`): конфиг
   `transports: ["telegram", "max"]`; вопрос публикуется во все включённые каналы,
   ожидание разрешается первым ответом (`Promise.race` с аккуратной отменой
   остальных — через `closeQuestion` с пометкой «отвечено в другом канале»).
2. Модель вопроса получает `deliveries: [{transport, messageId, chatId}]` вместо
   одного сообщения; `store` сохраняет их список; `closeQuestion` проходит по всем.
3. Ошибка одного канала не блокирует второй (если доставили хотя бы в один —
   вопрос живой); если не доставили ни в один — `next()` (GUI), как в 008.
4. Тесты: ответ из первого канала закрывает второй с пометкой; падение одного
   транспорта не мешает; поздний ответ проигравшего канала игнорируется и логируется;
   оба молчат — вопрос уходит в GUI.

## Критерии готовности

- [ ] `answerer` не знает про конкретные платформы — только про `transports[]`;
- [ ] закрытие проигравшего канала покрыто тестом (сообщение правится, кнопки сняты);
- [ ] ответ, пришедший из проигравшего канала, не меняет решение и виден в журнале;
- [ ] `node --test dsh-remote/test` зелёный.
