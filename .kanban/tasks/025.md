## Задача

Политика подтверждений: безопасность важнее удобства.

1. Конфиг `approvals`:
   - `tools: [...]` — какие инструменты вообще уводим удалённо (по умолчанию —
     только безопасные: чтение/запись в свой воркспейс; опасно-длинный список
     задаётся явно);
   - `denyRemote: [...]` — инструменты, которые **всегда** подтверждаются только
     в GUI (например `bash` с `git push`, деструктивные операции);
   - `onTimeout: "cancelled" | "unavailable"` (по умолчанию **cancelled** —
     отказ, а не «тихое разрешение»);
   - `ttlMs` (по умолчанию 30 минут, как у вопросов).
2. Реализовать решение политики ДО отправки в канал: инструмент вне списка или в
   `denyRemote` → сразу `next()`, в журнал запись «отдано GUI по политике».
3. Тесты: неизвестный инструмент → GUI; `denyRemote` → GUI; таймаут →
   `cancelled` (и `unavailable` при другой настройке); конфиг без полей → безопасные
   значения по умолчанию.

## Критерии готовности

- [ ] по умолчанию ни один опасный инструмент не подтверждается удалённо;
- [ ] таймаут никогда не даёт `allowed-once`;
- [ ] политика покрыта тестами на все ветки;
- [ ] в `/remote status` видно действующую политику (списки и `onTimeout`);
