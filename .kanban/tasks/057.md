## Задача

Живой инцидент 2026-11-13 (проект `dsh-vscode`): исполнитель задал вопрос, вопрос
ушёл **в GUI**, в MAX не пришёл, хотя выполнено `/remote on --all`.

Состояние в этот момент:

```json
"enabled": {
  "global": true,
  "workspaces": {
    "/Users/victor/projects/dsh-dispatcher": true,
    "/Users/victor/projects/dsh-vscode": false      // ← осталось от прежнего /remote off
  }
}
```

Причина: `resolve()` в `lib/domain/registry.js` смотрит по приоритету
**сессия → воркспейс → глобально**. Явный `workspaces[x] = false` перекрывает
`global = true`. А `setEnabled({kind:"global"})` (`lib/store.js:678`) и
`/remote on --all` (`lib/commands.js:1136`) меняют **только** `global` и явные
запреты не снимают.

Следствие: `status` рапортует «включено для всех проектов», а фактически часть
проектов выключена — самая опасная разновидность расхождения: человек уверен,
что канал работает.

## Требования

1. **Семантика `--all`**:
   - `/remote on --all` — режим включён **везде**: `global = true` и **все** явные
     запреты (`workspaces[*] = false`, `sessions[*] = false`) снимаются
     (удалением ключа или установкой `true` — выбрать и задокументировать
     одинаково для обоих мест);
   - `/remote off --all` — выключено везде: `global = false` и явные исключения
     `true` снимаются (иначе они молча перекрывают глобальный запрет).
2. **`status`/`setMode` не врут**: если для текущего проекта эффективное решение
   отличается от глобального, выводить оба факта («глобально включено; проект
   выключен явно» с источником `scope`). Сейчас пишется только итог.
3. **Логи**: при снятии запретов и при перекрытии глобального значения писать
   строку в журнал (`journal`, после 056) и `log()`.
4. **Тесты**:
   - `on --all` после `off` для проекта → `resolve` для этого проекта даёт `true`;
   - `off --all` после `on` для проекта → `resolve` даёт `false`;
   - `on`/`off` для проекта **после** `--all` продолжают работать (точечный
     запрет снова возможен и снова перекрывает глобальный);
   - `status` показывает перекрытие (строка со `scope: workspace`);
   - состояние, где ключи удалены, читается без ошибок (обратная совместимость).

## Критерии готовности

- [ ] `on --all` снимает прежние проектные запреты (тест);
- [ ] `off --all` снимает прежние проектные разрешения (тест);
- [ ] точечные `on`/`off` по-прежнему перекрывают глобальное значение;
- [ ] `status` честно показывает, что проект выключен при включённом глобальном;
- [ ] `node --test` и `bin/ci.sh --fast` зелёные.
