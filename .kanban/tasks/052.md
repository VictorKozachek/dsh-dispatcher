## Задача

После `/remote connect` → MAX привязка сохраняется, `connect` рапортует успех, но
**канал не поднимается**: вопросы падают на «канал не поднят» и уходят в GUI.

Причина найдена в `lib/features/commands.js`, `ensureTransport`:

```js
if (binding !== null && binding.transport === "relay") { … facade.set(relayTransport); return relayTransport; }
if (binding === null || binding.transport !== "telegram") { … return null; }   // ← max попадает сюда
```

Ветки для `binding.transport === "max"` нет, функция возвращает `null`, фасад
(`facade.current`) остаётся пустым. Парынг работает (он не через фасад), поэтому
скриншоты «сообщение с кнопкой дошло» относятся к прямым запросам, а вопросы
плагина не доходят никогда.

Воспроизведено вживую 2026-11-12 01:20–01:45: `state.bindings = {transport: max,
chatId: 549732759, userId: 13853411}`, `DSH_REMOTE_MAX_TOKEN` сохранён, прямой
`sendQuestion` через `createMaxTransport` **работает** (в том числе через TLS-фолбэк
на `platform-api.max.ru`), но вопрос из сессии в чат MAX не попадает.

## Требования

1. **Ветка max в `ensureTransport`** — по образцу relay:
   - прочитать привязку `store.read().bindings`, проверить `transport === "max"`;
   - взять токен через `createCredentialAccess` / `MAX_TOKEN_REF` (`DSH_REMOTE_MAX_TOKEN`);
   - создать транспорт `createMaxTransport({ token, chatId: binding.chatId,
     userId: binding.userId, apiBase: maxApiBaseFromConfig(config), log })`;
   - `facade.set(transport)`, вернуть его; проставить `__bindingKey` вида
     `max|<chatId>|<userId>` и `__token`, чтобы при смене привязки/токена транспорт
     пересоздавался (как в telegram/relay-ветках);
   - если токена нет — понятный warn, канал не поднимается (не падать).
2. **Старт поллинга**: `ensureTransport` для max должен запускать транспорт так же,
   как telegram ( `.start()` ), чтобы входящие сообщения/колбэки доходили.
3. **`/remote status` и `doctor`** должны показывать активный канал MAX как
   поднятый (а не «канал не поднят»).
4. **Тесты**: `ensureTransport` с привязкой max и токеном в credentials поднимает
   транспорт и ставит его в фасад; без токена — не поднимает и пишет warn; при
   смене chatId/токена транспорт пересоздаётся; вопрос после connect доставляется
   (фейковый транспорт либо фейковый fetch на `/messages`).
5. Регресс: telegram- и relay-ветки не ломаются (их тесты зелёные).

## Критерии готовности

- [ ] после `connect` → MAX фасад содержит max-транспорт (тест);
- [ ] вопрос из сессии уходит в MAX (тест на фейковом API: POST `/messages` с chat_id);
- [ ] при смене привязки транспорт пересоздаётся, поллинг стартует;
- [ ] без токена — warn и «канал не поднят», без падения;
