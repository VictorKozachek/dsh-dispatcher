## Задача

В шапке сообщения сейчас печатается **id пресета** (`standard`), а человек даёт
сессии осмысленное имя («Оркестратор», «Первый исполнитель», «Ревьювер»,
«Тестировщик») — и хочет видеть именно его.

Пример сейчас:

```
▸ dsh-memory · standard · 18:11 · до 18:41
```

Хочется:

```
▸ dsh-memory · Оркестратор · 18:11 · до 18:41
```

## Где лежит имя (найдено 18.11)

Имя сессии — это проекция `title` в кэше проекций DSH:

```
$DSH_HOME/storages/session_projcache/sessions/<sessionId>.json
→ record.rows.title.val            // "Оркестратор", "Ревьювер", "Второй исполнитель"
```

Формат: `{"ver":1,"seq":<n>,"val":"<имя>"}`. Файл один на сессию, имя
`session-<uuid>.json` (у старых сессий без префикса — `<uuid>.json`).
Проверено на живых данных: `session-8aac9774…` → «Оркестратор»,
`session-cf8c64d9…` → «Ревьювер», `session-25c353d8…` → «Второй исполнитель».

## Требования

1. `lib/present.js` (`resolveContext`): после получения `agentPreset` попытаться
   получить **имя сессии**, в таком порядке:
   a. публичный API хоста, если он есть: `ctx.get("sessions")`/`sessionController`
      с полем `title` (проверить, есть ли; если есть — использовать его, а не файл);
   b. файл кэша проекций (`$DSH_HOME/storages/session_projcache/sessions/<id>.json`,
      с вариантом без префикса `session-`), поле `record.rows.title.val`;
   c. если ничего — оставить текущее поведение (`agentPreset`).
2. В шапке печатать **имя сессии**, а пресет — не печатать (он технический). Если
   имени нет — печатать пресет как сейчас (обратная совместимость).
3. Чтение кэша — **не ронять** ничего: файла нет, JSON битый, поле отсутствует,
   нет прав → тихий откат на пресет (строка в debug-лог, не warn).
4. Длина: имя усекается по существующему правилу (`truncateWord`) до разумного
   предела шапки; не ломать общий бюджет `HEADER_LIMIT`.
5. Кэширование чтения: имя читается один раз на вопрос (не на каждое поле), и
   файл читается не чаще, чем нужно (никаких горячих циклов).
6. Тесты: файл с `title` → в шапке имя; файл без `title` → пресет; битый JSON →
   пресет и запись в debug; имя длиннее лимита → усечено; `DSH_HOME` не задан →
   дефолт; Telegram и MAX получают одинаковую шапку.

## Критерии готовности

- [ ] в шапке имя сессии, если оно задано (тест на временном `DSH_HOME`);
- [ ] без имени — прежнее поведение (регресс-тесты шапки из 047);
- [ ] битый/отсутствующий кэш не ломает вопрос (тест);
- [ ] длина шапки соблюдает `HEADER_LIMIT` (тест);
- [ ] `node --test` и `bin/ci.sh --fast` зелёные.
