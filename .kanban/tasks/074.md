## Задача

Живой разбор 2026-11-19 22:43: владелец ждал в MAX подтверждение действия
(«Allow this operation with **danger-full-access** permissions…» для `bash`), а
пришло оно **только в GUI**. Это не сбой доставки, а **политика по умолчанию**:

```js
DEFAULT_TOOLS      = [read_file, list_files, glob, grep]         // можно спрашивать удалённо
DEFAULT_DENY_REMOTE= [bash, shell, terminal, exec, run_command,
                      spawn, git_push, git_reset, delete_file, …] // только GUI
```

`decide()` возвращает `remote: false` с причинами `deny-remote` /
`tool-not-allowed`, и подтверждение честно уходит в GUI.

Проблема не в безопасности, а в **непрозрачности и отсутствии управления**:

1. Человек не знает, почему одно подтверждение пришло на телефон, а другое нет —
   в GUI/`status` причина не видна (она есть только в консольном логе).
2. Нет способа **разрешить себе** удалённое подтверждение для конкретного
   инструмента (например, `bash`), оставаясь в безопасном дефолте для остальных.
3. Нет способа посмотреть текущий allowlist/denyRemote без чтения конфига профиля.

## Требования

1. **Видимость причины**: `/remote status` (и панель) показывает политику
   подтверждений: `tools` (allowlist), `denyRemote`, `onTimeout`, `ttlMs`, и
   последнее решение с причиной (`allowed` / `deny-remote` / `tool-not-allowed`).
2. **Управление allowlist из чата**:
   - `/remote approvals` — показать текущее;
   - `/remote approvals allow bash` / `deny bash` — изменить `approvals.tools`
     и `denyRemote` в состоянии (не в конфиге профиля), с явным предупреждением
     для опасных инструментов («подтверждение `bash` с телефона = разрешение
     выполнения команд без проверки человеком за компьютером»);
   - изменения — в `state.json`, действуют сразу, без перезапуска.
3. **Журнал/аудит**: каждое решение политики пишется в аудит с причиной
   (`decision: "gui"`, `reason: deny-remote|tool-not-allowed`), чтобы по логу было
   видно, почему подтверждение не ушло в канал.
4. **Дефолт не меняем**: `bash` и прочие опасные по-прежнему только GUI, пока
   человек явно не разрешит.
5. Тесты: `status` показывает политику и последнюю причину; `allow bash` снимает
   `denyRemote`-запрет и подтверждение уходит в канал; `deny` возвращает; опасный
   инструмент требует явного `--force` либо подтверждения в чате; аудит содержит
   причину.

## Критерии готовности

- [ ] `/remote approvals` показывает allowlist/denyRemote/onTimeout/ttl и последнюю причину;
- [ ] `allow`/`deny` меняют политику без перезапуска и пишутся в состояние;
- [ ] подтверждение для разрешённого инструмента реально уходит в канал (тест);
- [ ] опасные инструменты по умолчанию по-прежнему в GUI;
- [ ] аудит фиксирует причину решения;
- [ ] `node --test` и `bin/ci.sh --fast` зелёные.
