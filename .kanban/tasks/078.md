## Задача

В шапке вопросов **до сих пор печатается пресет** (`standard`) вместо имени сессии
(«Оркестратор»), хотя `#068`/`#069` имя находят и диагностика это подтверждает:

```
context.resolve {"sessionId":"8aac9774…","foundTitle":true,"titleSource":"agent-id",
                 "workspace":"dsh-dispatcher","preset":"standard", …}
```

а следом `question.send` → в MAX уходит `▸ dsh-dispatcher · standard · …`.

## Причина (точная)

`dsh-remote/lib/answerer.js`, создание вопросов пачки (≈ строка 741):

```js
const createdList = createQuestions(items, {
  sessionId,
  workspace,
  role: questionContext.role,       // ← передаётся
  taskId, branch, worktree, quickReplies, lang, chatId, threadId, now, log,
  // sessionTitle: questionContext.sessionTitle   ← НЕ передаётся
});
```

`resolveContext` кладёт имя в `questionContext.sessionTitle`
(`answerer.js` ~591), модель `RemoteQuestion` сохраняет его (`domain/question.js:107`),
`renderHeader` умеет печатать (`present.js`, `displayRole`), но **между ними
значение теряется**: контекст для `createQuestions` собран явным списком полей, и
`sessionTitle` в него не попал. Поэтому `question.sessionTitle === null` →
`displayRole` падает на `context.role` = `agentPreset` = `standard`.

Проверено: в изоляции `resolveContext` + `createQuestion` + `renderBody` дают
`▸ dsh-dispatcher · Оркестратор · 19:51 · до 20:51`, а живой путь — `standard`.

## Требования

1. Передавать `sessionTitle: questionContext.sessionTitle ?? null` в
   `createQuestions(...)` в `answerer.js`.
2. **Тест на регресс именно этой проводки** (а не только `resolveContext`):
   `answerer.handler` с фейковым `ctx.sessions` (header с `agentPreset: "standard"`)
   и `session_projcache` с `title.val = "Оркестратор"` → вопрос уходит в канал, и
   **шапка в отправленном тексте содержит «Оркестратор», а не «standard»**.
   Проверять реальный `sendQuestion`-payload (фейковый транспорт), а не внутреннее поле.
3. Проверить остальные места, где контекст собирается явным списком (поиск по
   `questionContext.` в `answerer.js`), чтобы больше ни одно поле не терялось —
   лучше передавать `...questionContext` целиком и добавлять к нему остальное.
4. Убедиться, что `answerer.spec`/`present.spec` не полагаются на старое поведение.

## Критерии готовности

- [ ] в отправленном тексте шапка содержит имя сессии (тест на payload);
- [ ] без имени — прежний пресет (регресс `#068`);
- [ ] ни одно поле контекста не теряется при сборке (нет «магического списка»);
- [ ] `node --test` и `bin/ci.sh --fast` зелёные;
- [ ] живая проверка: шапка в MAX = имя сессии (после перезапуска).
