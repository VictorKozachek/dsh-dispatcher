## Задача

Сделать диагностику, по которой понятно «что сломалось и что делать».

1. `dsh-remote/lib/doctor.js` — health-модель: набор проверок с полями
   `{id, status: "ok"|"warn"|"fail", detail, action?}`:
   - транспорт(ы): привязка, токен (резолвится ли ссылка), последний апдейт/пинг;
   - `relay`: `/healthz`, состояние WS, попытки переподключения;
   - `credentials`: `describe()` по нужным ссылкам, `writable`, приоритет env;
   - `state`: читается ли `state.json`, версия схемы (см. 032), права файла;
   - `lock`: занят ли поллер, кем и с какого времени;
   - `timers`: нет ли «повисших» TTL-таймеров (по счётчикам из 031).
2. `/remote doctor` — человекочитаемый вывод с итогом `ok/warn/fail` и кодом
   возврата (0/1/2), `/remote doctor --json` — машиночитаемо (для скриптов и 036).
3. Переиспользовать существующий `/remote doctor` из 010, не ломая его вывод:
   расширить, а не переписать (старые строки остаются узнаваемыми).
4. Тесты: каждая проверка в трёх состояниях; `--json` парсится; код возврата
   соответствует худшему статусу; отсутствие сервисов не даёт исключения.

## Критерии готовности

- [ ] `--json` стабилен по структуре и покрыт тестом;
- [ ] каждая `fail`-проверка содержит `action` «что делать»;
- [ ] код возврата = худший статус (0/1/2);
- [ ] нет секретов в выводе (тест на токен);
- [ ] `node --test dsh-remote/test` зелёный.
