## Задача

После `#076` события журнала должны нести контекст (`sessionId`, `workspace`,
`preset`), но в живом `~/.dsh/remote-control/log.jsonl` его **нет**:

```json
{"ts":"2026-11-23T12:51:21.640Z","event":"question.send","transport":"max",
 "shortId":"70104421","detail":"{\"chatId\":549732759,\"options\":3,…}"}
```

ни `workspace`, ни `sessionId`, ни `preset`. Из-за этого снова невозможно понять,
из какого проекта пришёл вопрос (и остаётся неразобранным старый вопрос владельца:
«вопросы из других воркспейсов не доходят»).

## Причина (точная)

1. `lib/answerer.js` (`journalEvent`) контекст подмешивает:
   ```js
   const base = journalContextFor(fields?.shortId);
   const enriched = base === null ? fields : { ...base, ...fields };
   journal?.record?.(event, enriched);
   ```
2. Но `lib/journal.js` (`record`) собирает запись **явным списком полей** и всё
   остальное выбрасывает:
   ```js
   const entry = { ts, level, event,
     ...(transport ? {transport} : {}),
     ...(shortId ? {shortId} : {}),
     ...(detail ? {detail} : {}) };
   ```
   `workspace`/`sessionId`/`preset` в этот список не входят → теряются.

Дополнительно: `question.send`/`question.sent` эмитятся в цикле публикации, а
`journalContexts.set(shortId, …)` происходит позже (`answerer.js:763`) — надо
проверить, что контекст доступен уже на `question.send` (иначе первое событие всё
равно без контекста).

## Требования

1. `journal.record` пишет **аддитивные поля контекста**, если они переданы:
   `workspace` (basename), `sessionId` (маска, как `8aac9774…`), `preset`.
   Никаких полных путей.
2. Убедиться, что контекст доступен с **первого** события вопроса: регистрировать
   `journalContexts` до публикации (или передавать контекст явным аргументом в
   `journalEvent` для `question.send`).
3. Тест на **реальный файл журнала**: после `answerer.handler` в `log.jsonl`
   каждая строка соответствующего `shortId` содержит `workspace`/`sessionId`;
   `question.send` — тоже.
4. Панель истории (`journal-read`): фильтр по проекту начинает работать на живых
   данных — вернуть его из `#070` (там снят именно из-за отсутствия поля).
5. Обратная совместимость: старые строки без полей читаются как раньше.

## Критерии готовности

- [ ] `question.send`/`sent`/`answer.*` в файле содержат `workspace`/`sessionId`/`preset` (тест на файле);
- [ ] контекст есть уже у первого события вопроса (тест);
- [ ] фильтр по проекту в панели работает на живых данных (тест);
- [ ] полных путей и текстов ответов в журнале нет (тест);
- [ ] `node --test` и `bin/ci.sh --fast` зелёные.
