## Задача

Клиентская половина: таб «Удалённое управление» в правом сайдбаре DSH.

1. `dsh-remote/lib/client.js` — клиентский бандл (`exports["./client"]`,
   `dsh.client: { platform: "web", inject: [...] }`); панель со статусом:
   транспорт и привязка, включённые воркспейсы, открытые вопросы (сессия/задача/дедлайн),
   кнопки «Тест», «Снять вопрос», «Обновить», последние 20 строк журнала (без секретов).
2. **Важно про версию сборки.** Исходники в `~/projects/deepseek-harness`
   (`0.1.2-alpha.2`) старше установленного DSH: в них нет сервиса
   `sidebarRightTabs` и слотов `sidebar.right.*`, а клиентская половина
   `dsh-kanban` использует именно их и работает. Ориентир — установленная сборка
   и `dsh-kanban/lib/client.js` (`ctx.sidebarRightTabs.register(...)`,
   `ctx.slots.inject("sidebar.right.pane.tab", ...)`), проверка — в живом профиле.
   Если в конкретном профиле API не смонтирован — честно сдать панель как
   «недоступна в этой сборке» и описать, чего не хватило.
3. Host-канал: если нужен запрос из GUI к host-половине — по образцу
   `~/projects/dsh-kanban/dsh-kanban/lib/children.js` и `card-actions.js`
   (только чтение, не менять). Минимальный вариант допустим: панель показывает
   статус из `state.json` через workspace-files Remote, если файл лежит в воркспейсе.
   Но состояние в `~/.dsh/remote-control/` — значит нужен host-канал; выбери его и
   опиши в README плагина.
4. Тесты: `test/client.spec.js` — чистая логика панели (форматирование статуса,
   фильтрация журнала, сортировка вопросов по дедлайну) без DOM.
5. Обновление `dsh-remote/package.json`: `exports["./client"]`, `files` (добавить
   клиентские файлы), `dsh.client.inject` — минимальный набор пакетов DSH.
