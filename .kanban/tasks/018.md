## Задача

Транспорт `relay` в плагине: тот же контракт, другой адресат.

1. `dsh-remote/lib/transport/relay.js`: реализация `QuestionTransport` поверх
   HTTP/WebSocket из 016 (`sendQuestion` → POST вопроса, `closeQuestion` → PATCH,
   `onAnswer` ← WS `question.answered`, `healthCheck` → `/healthz`).
2. Конфиг: `relay: { url, deviceToken, keyId }`; токен устройства — через
   `ctx.credentials` (ссылка, не значение); `/remote connect relay` — ввод URL и
   pairing-кода, `/remote status` показывает состояние соединения.
3. Переподключение WS с backoff, fallback на long-poll, идемпотентность отправки
   (повтор с тем же `clientId` не создаёт дубль).
4. Тесты на фейковом `fetch`/WS: отправка вопроса, ответ, разрыв соединения →
   переподключение, повтор отправки не дублирует, неверный токен → внятная ошибка.

## Критерии готовности

- [ ] реализует контракт и проходит `checkTransport`;
- [ ] ни одного сетевого вызова в тестах;
- [ ] pairing-код и токен не попадают в логи/состояние;
- [ ] `node --test dsh-remote/test` зелёный.
