# Спека 010: Настоящее зеркало — правка хоста DSH (settle/cancel + событие «отвечено»)

Статус: нарезана 17.11 по решению владельца (вариант A).
Основание: аудит `#058` (`docs/research/gui-question-retract.md`) доказал, что без
правки хоста полное зеркало невозможно: у `UserQuestionService` нет метода снять
живой вопрос, ответ GUI приходит только как возвращаемое значение waterfall, а
события «в GUI ответили» в forwarded-allowlist нет.

## Что нужно от хоста

1. **`settle(agent, callId, answer)`** — закрыть **живой** (не `continued`) вопрос
   так, будто на него ответили: карточка в GUI исчезает, `ask()` возвращает этот
   ответ. Сейчас `answer()` работает только для timed-`continued`.
2. **`cancel(agent, callId, reason)`** — снять живой вопрос: карточка исчезает,
   `ask()` отклоняется `ASK_ABORTED` (или отдельным кодом), сессия получает
   понятную причину.
3. **Событие `user-questions/resolved`** (или расширение проекции): `{callId,
   agentId, outcome: 'answered'|'cancelled', source: 'gui'|'remote'}` — чтобы
   плагин узнавал «в GUI ответили» **до** возврата waterfall и мог погасить своё
   сообщение в мессенджере.
4. **Идемпотентность**: повторный `settle`/`cancel` — no-op с `false`, без падения;
   гонка «GUI ответил и `settle` одновременно» → побеждает первый, второй получает
   `false`.

## Как это использует наш плагин

- Режим `mirror` (059/063) **определяет возможности хоста** при старте:
  `typeof service.settle === "function"` и наличие события;
- если есть — полное зеркало: вопрос уходит и в канал, и в GUI; первый ответ
  побеждает: ответ из канала → `settle(callId, answer)`; ответ GUI (событие) →
  сообщение в канале гасится;
- если нет — деградация B: GUI — источник истины, мессенджер — уведомление
  (и `status` честно пишет, что хост не умеет снимать).

## Как доставить предложение

DSH закрытый (Electron-приложение, `app.asar`), поэтому:
1. **Предложение-патч** в `docs/proposals/dsh-user-questions-settle.md`: точные
   места в `dsh-user-questions/lib/index.js`, `dsh-api-remotes/lib/index.js`,
   `dsh-client-ui-user-questions/lib/client.js`, эскиз кода и тестов;
2. **Патч-скрипт не делаем**: правка `app.asar` ломает подпись приложения и
   перезаписывается обновлением — это осознанное ограничение, записать в документе;
3. Когда/если хост получит API — наш плагин включает полное зеркало без правок
   (feature-detect), а `063` уже будет готов.
