# Спека 001: Удалённое управление вопросами агента

Статус: готова к нарезке (карточки 001–010 в `backlog`).
Концепция: [docs/CONCEPT.md](../../docs/CONCEPT.md).

## Зачем

Агент, задавший вопрос через `ask_user_question`, блокируется до ответа человека.
Если человек не за клавиатурой, сессия простаивает. Нужно, чтобы вопрос уходил в
мессенджер (Telegram, затем MAX), а ответ возвращался в ту же сессию как результат
инструмента — с маркировкой воркспейса, задачи и роли.

## Требования

1. **Перехват.** Плагин `dsh-remote` регистрирует ответчик события
   `user-questions/request`. При выключенном удалённом режиме — `next()` (поведение
   DSH не меняется). При включённом — вопрос уходит в транспорт, ответ
   возвращается как `AskUserQuestionAnswer`.
2. **Изоляция ядра.** Ядро DSH и сторонние плагины не патчатся; используются только
   публичные сервисы (`userQuestions`-событие, `commands`, `sessions`,
   `credentials`).
3. **Подключение командой.** `/remote connect` — выбор транспорта и ввод токена
   через локальный вопрос, pairing-код, сохранение привязки. Далее
   `/remote on|off|status|test|who|disconnect|doctor`.
4. **Адресация.** В сообщении видно: воркспейс (cwd сессии), номер задачи с доски
   (если владелец карточки — эта сессия), роль (`agentPreset`), время и дедлайн.
5. **Ответ.** Кнопки-варианты (одна на строку), «Другой ответ…» и свободный
   текст/reply; после ответа сообщение правится, кнопки снимаются. Ответ
   применяется ровно один раз.
6. **Транспорт-абстракция.** `sendQuestion / closeQuestion / onAnswer / start /
   stop / healthCheck`, лимиты в `caps`; `fake`-транспорт для тестов; Telegram
   первым, MAX — следующим.
7. **Устойчивость.** TTL 30 мин (напоминание правкой за 5 мин, затем `expired` с
   эскалацией), недоставленный вопрос — очередь с повтором, при недоступности
   транспорта вопрос отдаётся GUI, «осиротевшие» после рестарта вопросы — `cancelled`.
8. **Безопасность.** Allowlist по user id + chat id, pairing-код с TTL 10 мин,
   токен только через `ctx.credentials` (reference, не значение), маскирование в
   логах, один поллер на токен (lock-файл), redact тела вопроса.
9. **Состояние.** `~/.dsh/remote-control/state.json` (атомарно, chmod 600) и
   `log.jsonl` без секретов; репозиторий проекта — только код и документация.
10. **Тесты.** Юнит- и интеграционные тесты на `fake`-транспорте: домен, TTL,
    дедуп, allowlist, роутинг нескольких сессий, рестарт. Сеть в тестах не нужна.

## Критерии готовности MVP

- [ ] `/remote connect` доводит до привязки бота, `/remote status` показывает её;
- [ ] вопрос из сессии приходит в Telegram и разблокирует сессию ответом (кнопка
      и свободный текст);
- [ ] при выключенном режиме поведение DSH не меняется (вопрос в GUI);
- [ ] при недоступном мессенджере вопрос уходит в GUI, а не теряется;
- [ ] нажатие кнопки дважды или ответ из чужого чата ничего не ломают;
- [ ] тесты проходят без сети; документация объясняет, как завести бота.

## Вне скоупа

- мобильные приложения и свой релей (спека 002);
- режим `mirror` (вопрос и в GUI, и в телефоне) — фаза 2;
- уведомления о событиях канбана — фаза 2;
- групповые чаты и несколько людей-адресатов;
- деплой на сервер, TLS-терминация, многопользовательский режим.
