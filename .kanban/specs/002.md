# Спека 002: MAX как второй канал и гибридный режим

Статус: нарезана (карточки 011–015).
Концепция: [docs/CONCEPT.md](../../docs/CONCEPT.md) §9–10.
Справка по API: [docs/research/messengers.md](../../docs/research/messengers.md) §2.

## Зачем

Telegram закрывает сценарий «ноутбук за NAT» с нулевой инфраструктурой, но у него
есть риск доступности в РФ. Второй канал (MAX) должен закрыть этот риск, а
гибридный режим — случай, когда человек у ноутбука, но хочет видеть вопрос и в
телефоне, не теряя вопрос при молчании мессенджера.

## Требования

1. **MAX-транспорт** по тому же контракту `QuestionTransport`: инлайн-кнопки,
   колбэки (`POST /answers` — один вызов вместо двух у Telegram), правка
   сообщения, дедуп по композитному ключу (глобального `update_id` нет), свой
   троттлинг (2 msg/с в чат, `retry_after` не документирован), лимит 4000 символов.
2. **Доставка обновлений**: long polling `GET /updates` как best-effort (документация
   MAX называет его не-production) либо webhook через туннель на loopback (DSH не
   умеет `--host 0.0.0.0`, см. `docs/research/dsh-hooks.md` §7.1). Выбор — в
   конфиге, внятная ошибка, если выбран webhook без туннеля.
3. **Два канала одновременно**: один вопрос уходит в оба, первый ответ
   принимается, второй канал закрывается с пометкой «отвечено в другом».
4. **Гибридный режим**: вопрос публикуется в мессенджер; если ответа нет N секунд —
   **до** публикации в GUI зовётся `next()` и вопрос уходит в браузер; поздний
   ответ из мессенджера доставляется в сессию `sessionController.prompt`
   (`mode: 'steer'`) с явной пометкой. Режим выключен по умолчанию.
5. **Уведомления доски** в тот же канал: карточка ушла в `ready`, `blocked`,
   `todo` недобор — короткое сообщение без подмены карточки (доска остаётся
   источником истины, статусы двигает только `bin/task-move.sh`).
6. **Группировка по проектам**: свой чат или топик на проект, чтобы вопросы разных
   воркспейсов не смешивались; маршрутизация по `chatId` + `threadId`.

## Вне скоупа

- мобильные приложения и свой релей — спека 003;
- несколько людей-адресатов и роли в чате (кто именно может отвечать);
- голосовые ответы и вложения.
